# RAG / Agent 评测集

已建立数据集和执行脚本，尚未运行真实模型评测。线上检索逻辑不变。

## 文件

`datasets/geochronology_v1.json` 包含 10 条人工标注用例：7 条可回答问题和 3 条资料缺失问题，覆盖直接查找、同义表达、跨片段理解、错误前提和缺失信息。

资料来源是项目根目录的《铷锶等时线定年_专业测试资料.md》。其中 QL-27 本身是虚构教学情景，标注只以文档记录为准，不代表真实实验事实。

## 字段含义

- `source`：文档文件名、当前数据库文档 ID、SHA-256 和分块数量。
- `id`：用例编号。
- `category`：问题类型。
- `question`：发给 /agent/chat 的问题。
- `expected_knowledge_base_id`：期望检索的知识库。
- `relevant_chunk_indices`：包含答案或“资料缺失”依据的相关分块，序号从 0 开始。它们不是要求逐字引用的固定列表，也不表示每一块都必须出现才能回答正确。
- `answerable`：文档能否提供问题要求的事实。false 时，正确行为是说明缺失，并非接口报错或 sources 必须为空。
- `expected_points`：人工检查回答时应包含的要点，允许同义表达。
- `forbidden_claims`：应避免的错误结论或编造行为，不是用于简单子串匹配的禁词表。
- `evidence_quotes`：从原文摘出的依据，便于复核标注；有些只是定位用短语，需要结合所在段落理解。

标准答案字段只能用于评分，不能随问题一起发给 Agent，否则会泄露答案。

## 当前标注与验证范围

用例对照原文及此前实际返回的 5 个分块标注。已检查 JSON 可解析、10 个编号不重复、字段完整、索引范围为 0 到 4、证据摘录确实存在于原文，以及原文件 SHA-256 与数据集一致。

没有在这一步重新从数据库自动核验完整分块，也没有调用模型。修改原文、分块参数或重新上传到不同文档 ID 后，需要复核 source 和分块标注，不能直接复用旧分块编号。

## 后续怎么运行

run_eval.py 逐条请求 POST /agent/chat，只发送：

```json
{
  "question": "该用例的 question 内容"
}
```

每条保存完整响应、HTTP 状态、耗时与用例 ID。失败请求也必须记录，不能从结果中丢弃。执行会产生真实聊天和 Embedding API 用量。

第一版先统计接口成功率、工具调用中是否检索目标知识库，以及最终 sources 对标注相关分块的覆盖情况。回答要点、引用是否支持结论和资料缺失时是否编造，先人工检查，不以关键词命中直接代替答案正确性。

Agent 可以多次检索、每次 top_k 也可能不同，因此所有 sources 的合并覆盖率不能直接称为固定 K 的 Recall@K。若要比较 Recall@3 或 Recall@5，需要另对检索工具设置固定 K 进行测试。

## 使用边界

这 10 条来自同一个小文档，用于建立开发基线、发现回归问题。它不能代表企业级检索质量，也不能据此声称整个系统不存在幻觉。当前有两个知识库，但主要测试地质主题；后续应增加其他主题、无匹配知识库问题及独立测试集。

## 执行命令

先保持 FastAPI 在 8000 端口运行。以下命令均在 ai-service 目录执行。

先运行统计与失败处理测试，不调用任何真实模型：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s evals -p test_run_eval.py
```

再只运行第一条真实用例：

```powershell
.\.venv\Scripts\python.exe evals/run_eval.py --limit 1
```

确认返回和保存正常后，运行全部 10 条：

```powershell
.\.venv\Scripts\python.exe evals/run_eval.py
```

可选参数：--base-url http://127.0.0.1:8000、--timeout 300、--dataset 数据集路径。脚本顺序执行，不并发、不自动重试。超时只是客户端停止等待，服务端可能仍在处理，不能把重跑当成没有成本的操作。

## 输出与统计口径

每次运行建立独立的 evals/results/UTC时间_随机编号 目录，避免覆盖之前结果。该目录已被 Git 忽略。目录包含：

- results.jsonl：每行一个用例，保存完整标注、实际响应、HTTP 状态、原始响应体、错误、耗时及检索指标。每完成一条立即刷新写入。
- summary.json：数据集哈希、地址、超时设置、已尝试/成功/失败/未完成数量、接口成功率、目标库命中率、平均证据覆盖和成功请求耗时。
- review.md：问题、预期要点、不应出现的结论、实际回答，以及待填写的人工审阅结论。

目标库命中表示实际文档检索工具使用过目标库 ID。仅在候选列表中出现目标库不计命中；同时检索了其他库会记录 unexpected_knowledge_base_ids。

证据覆盖仅比较目标 document_id 下的分块编号，去重后计算“命中相关分块数 / 标注相关分块数”。其他文档即使有同样的分块编号也不算命中。它不是回答正确率，也不是固定 K 的 Recall@K。

汇总中失败请求按未命中与零覆盖计入分母，避免剔除失败后高估效果。响应耗时只对成功样本单独统计；P95 使用最近秩定义，小样本下不稳定，仅供开发观察。

人工审阅要看含义与引用依据，不要把 answerable=false 判为请求失败，也不要直接按 expected_points 的字面字符串判断答案。两段原文重复支持同一结论时，不要求为了高覆盖率把它们全部塞给模型。

Ctrl+C 时，已完成记录和汇总仍会保存；未完成用例单独计数，不当成已测成功。统计分母为实际得到记录的请求数。完整对比时应确认 uncompleted_count 为 0、数据集一致，并记录运行服务的模型设置和代码版本。
